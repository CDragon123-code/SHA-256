# SHA-256 关键路径分析（17-5）

> 本文档回答外部最常见的问题：「为什么 66.7MHz 而不是 98MHz？」
> 数据来源：`reports_checks_15ns.rpt`（15ns 签核时序报告）

## 1. 一句话结论

SHA-256 压缩函数的关键路径穿过 **40 级组合逻辑**，数据路径（Q→D）cell + net 延迟 **14.14 ns**。数据到达时间 **15.852 ns** = launch 时钟 1.155 ns（含 CTS）+ clk-to-Q 0.555 ns + 数据路径 14.142 ns。98 MHz（10.2 ns 周期）无法覆盖这条路径；15 ns（66.7 MHz）刚好满足，setup slack = +0.184 ns。

## 2. 关键路径概要

| 指标 | 数值 |
|------|------|
| 起点 | `_10910_` (DFF: sky130_fd_sc_hd__dfxtp_1) |
| 终点 | `_11097_` (DFF: sky130_fd_sc_hd__dfxtp_1) |
| 时钟域 | core_clock |
| 路径类型 | setup (max) |
| 数据路径 (Q→D) cell+net | 14.142 ns（40 级组合逻辑） |
| clk-to-Q | 0.555 ns（起点 DFF `_10910_`） |
| launch 时钟延迟 (CTS) | 1.155 ns |
| 数据到达时间 | 15.852 ns（= 1.155 + 0.555 + 14.142） |
| 时钟周期 | 15.000 ns (66.7 MHz) |
| capture 时钟延迟 (CTS) | 1.180 ns |
| 库 setup time | 0.144 ns |
| 数据要求时间 | 16.036 ns |
| **Setup slack** | **+0.184 ns (MET)** |
| Hold slack | +0.024 ns (MET) |

## 3. 为什么 98 MHz 失败

98 MHz 对应时钟周期 10.204 ns：

| 频率 | 周期 | 所需到达时间 | 实际到达时间 | Slack |
|------|------|-------------|-------------|-------|
> 注：表中「所需到达时间」= 时钟周期 + capture 时钟树延迟(1.18) − 库 setup(0.144)。

| 98 MHz | 10.20 ns | 10.20 + 1.18 - 0.144 = 11.24 ns | 15.852 ns | **-4.61 ns (VIOLATED)** |
| 70 MHz | 14.29 ns | 14.29 + 1.18 - 0.144 = 15.33 ns | 15.852 ns | -0.52 ns (VIOLATED) |
| 66.7 MHz | 15.00 ns | 15.00 + 1.18 - 0.144 = 16.04 ns | 15.852 ns | **+0.18 ns (MET)** |

**结论**：关键路径数据到达时间 15.852 ns 是硬底线（= 1.155 时钟延迟 + 0.555 clk-to-Q + 14.142 数据路径），时钟周期必须 ≥ 15 ns 才能满足 setup。数据路径本身 14.142 ns 对应频率上限 1/14.142 ≈ 70 MHz；加上 capture 时钟树延迟 1.18 ns 和 setup 0.144 ns 后，可签核频率降为 66.7 MHz。

## 4. 关键路径逻辑深度分析

从起点 DFF 的 Q 端到终点 DFF 的 D 端，共经过 **40 级组合逻辑**（排除 8 级 CTS buffer 和 2 个 DFF）：

| 标准单元类型 | 出现次数 | 功能 | 平均延迟/级 |
|-------------|---------|------|------------|
| a21oi_1 | 9 | AND2-OR2-INV (2输入) | ~0.35 ns |
| o21ai_0 | 6 | OR2-AND2-INV (2输入, 驱动增强) | ~0.40 ns |
| xnor3_4 | 4 | 3输入异或非 (驱动×4) | ~0.44 ns |
| o21bai_1 | 4 | OR2-AND2-INV-B (带反相输入) | ~0.38 ns |
| nand2_1 | 4 | 2输入与非 | ~0.11 ns |
| xor3_4 | 2 | 3输入异或 (驱动×4) | ~0.35 ns |
| or2b_2 | 2 | 2输入或 (带反相输入, 驱动×2) | ~0.35 ns |
| o211ai_1 | 2 | OR2-AND2-INV (3路) | ~0.30 ns |
| o2111ai_1 | 2 | OR2-AND2-INV (4路) | ~0.30 ns |
| nand3_1 | 2 | 3输入与非 | ~0.15 ns |
| a31oi_1 | 2 | AND3-OR2-INV | ~0.32 ns |
| 其他 (nand4, o211a 等) | ~3 | 混合复合门 | ~0.30 ns |
| **合计** | **~40** | — | **平均 ~0.37 ns/级** |

> **关键观察**：路径以 `a21oi` / `o21ai` 系列复合门为主导（15 级，占 37.5%），这些是 SHA-256 压缩函数中 `Ch` / `Maj` / `Σ` 逻辑的硬件实现。XNOR3/XOR3 共 6 级，对应 `Σ0` / `Σ1` 的循环移位加法。

## 5. 根因分析

### 5.1 架构层面

SHA-256 压缩函数每轮包含：
- **Ch(x,y,z)** = (x & y) ^ (~x & z) —— 2 级 AND-OR-INV
- **Maj(x,y,z)** = (x & y) ^ (x & z) ^ (y & z) —— 3 级 AND-OR-INV
- **Σ0/Σ1** = ROTR(x,2) ^ ROTR(x,13) ^ ROTR(x,22) —— 3 级 XOR
- **T1 = h + Σ1(e) + Ch(e,f,g) + K[i] + W[i]** —— 加法器链

关键路径穿过 **T1 计算链**：Σ1 → Ch → 32-bit 加法器 → W[i] 选择 → 下一轮寄存器。单轮组合延迟约 2-3 ns，64 轮迭代中关键路径跨越多轮的流水线级。

### 5.2 为什么无法达到 98 MHz

参考论文 [LDFranck/SHA-256] 达到 97.89 MHz，差异可能来自：

1. **流水线深度不同**：参考设计可能插入了更多流水线级（如每轮 SHA-256 运算拆分为 2-3 级流水线），降低了每级组合深度
2. **加法器架构不同**：32-bit 加法器可用 Brent-Kung / Kogge-Stone 前缀树（延迟 O(log n)）替代行波进位（延迟 O(n)），但面积更大
3. **综合策略不同**：OpenLane 可能用了更激进的时序优化（retiming / 复制 / 门尺寸调整）

### 5.3 本项目的取舍

本项目用 **手工 OpenROAD 流程**（非 OpenLane），没有自动 retiming。15 ns 签核是一个保守但可靠的选择：
- ✅ setup/hold 双正 slack（+0.184 / +0.024）
- ✅ FIPS 180-4 后仿通过
- ✅ 10 项 signoff 全过
- ✅ 晶体管级 LVS 闭环

频率 66.7 MHz 低于参考 97.89 MHz 是**手工流程的代价**，但换来的是完整的 signoff 链和可复现性。

## 6. 可能的优化方向（未实施，仅记录）

| 优化 | 预期收益 | 代价 |
|------|---------|------|
| 插入流水线级（每轮 SHA-256 拆 2 级） | 频率 ×1.5~2 | 吞吐延迟 +1 周期，面积 +5% |
| 32-bit 前缀树加法器替代行波进位 | 关键路径 -2~3 ns | 面积 +10% |
| OpenLane 自动 retiming | 频率 ×1.2~1.3 | 需 Docker 环境 |
| 关键路径门尺寸调整（size up） | -0.5~1 ns | 面积 +2% |

> 以上优化均未实施。当前 15ns 版本已通过全部 signoff，作为可流片版本固定。
